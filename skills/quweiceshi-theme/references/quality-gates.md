# 交付检查

## 1. 静态检查

在项目根目录运行：

```powershell
node skills/quweiceshi-theme/scripts/check-theme.mjs <slug>
```

脚本会检查：

- 页面、配置、图标和首页卡片是否存在。
- 六个维度、题目数量、`d` 取值范围和维度覆盖。
- 4 位暗号唯一、非连续，并已写入 `quiz-passwords.md`。
- 一直点同一选项是否会得到最高分或最低分。
- SEO、图标引用、背景形状池、主题 token、页脚声明。
- 测试页是否错误地放了返回首页入口。
- 页面引用的本地资源是否存在。

任何一项失败都先修复，不要带着失败进入浏览器检查。

## 2. 本地预览

```powershell
python -m http.server 5173
```

打开 `http://127.0.0.1:5173/<slug>.html`。静态资源必须从根目录加载，不能直接用 `file://` 判断。

## 3. 浏览器检查

至少覆盖：

| 端 | 宽度 | 高度 |
| --- | --- | --- |
| 手机 | 390 | 844 |
| 平板 | 820 | 1180 |
| PC | 1440 | 900 |

每个尺寸确认：

- 暗号输入框和按钮都是 48px 高，输入框在窄屏不溢出。
- 输入错误暗号仍停留在入口页并显示错误提示；输入正确暗号进入第一题。
- 4 个选项完整可见；hover 有反馈，按下有轻微缩放，不闪烁。
- 选中后有明确边框与底色；切到下一题后旧选中状态完全消失。
- “上一题”可返回且保留已选答案，图标与 12px 加粗文字同尺寸。
- 答完后出现六边形雷达图和结果解释，解释文案在图表下方。
- 页脚只有测试免责声明，没有支持者、邮箱或联系方式。
- 页面没有横向滚动；浏览器控制台没有报错，网络面板没有 404。

## 4. 回归

新增主题后至少再打开 `index.html` 和一个已有主题，确认：

- 首页卡片能进入新页面，主题数量与卡片数一致。
- 新主题的 CSS token 和背景形状没有影响其他页面。
- 所有页面的主/次按钮结构一致，只有颜色不同。

## 5. 收尾

```powershell
git diff --check
git status --short
```

- 确认 `quiz-passwords.md` 没有被跟踪。
- 确认 diff 只包含当前主题需要的文件。
- 不运行 ESLint、前端 build 或 typecheck，除非用户明确要求。
